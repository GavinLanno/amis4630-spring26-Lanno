## 5. Code Quality Coaching (Non-Scoring)

- **Missing SUBMISSION.md**: The rubric's submission guidelines require a top-level `SUBMISSION.md` with test credentials and security practice descriptions. Admin credentials were only discoverable in `docs/AI-USAGE.md` and seed defaults in `Program.cs`. This is not a scoring deduction per the rubric criteria, but should be provided for grader convenience.

- **TypeScript build error in test file**: [frontend/src/pages/CheckoutPage.test.tsx](frontend/src/pages/CheckoutPage.test.tsx#L83-L93) — The mock `placeOrder` return value has `shippingAddress` typed as an object (`{ fullName, addressLine1, ... }`) but the `Order` type likely expects a `string`. This causes `tsc -b` to fail. While Vitest runs tests successfully, `npm run build` fails on a fresh clone. Fix the mock to return `shippingAddress` as a string to match the backend's concatenated format.

- **Typo in filename**: The DbContext file is named [LisitngContext.cs](backend/HelloWorldApi/Data/LisitngContext.cs) (misspelling of "Listing"). The class is correctly named `ListingContext` internally. Consider renaming the file for consistency.

- **Admin seed password in source code**: [Program.cs](backend/HelloWorldApi/Program.cs#L128) — The fallback admin password `"AdminPass1"` is hardcoded as a default. While it's configurable via environment variables (good), the fallback means the password is in source control. For production, remove the fallback and require the env var.

- **CheckoutController is vestigial**: [CheckoutController.cs](backend/HelloWorldApi/Controllers/CheckoutController.cs) appears to be a standalone endpoint that doesn't actually process orders — it just returns a message. The real order placement is handled by `OrdersController.PlaceOrder`. This dead endpoint could be removed to reduce confusion.

- **Refresh token lookup is O(n)**: [AuthController.cs](backend/HelloWorldApi/Controllers/AuthController.cs#L158-L165) — `RefreshToken` loads all active tokens and iterates with `VerifyHashedPassword`. While secure (hashed tokens), this scales poorly. Consider using a lookup-friendly prefix or indexed column.
